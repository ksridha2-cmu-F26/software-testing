1. Summary

In this lab, I changed the SocialNetwork class to implement ISocialNetwork and gradually moved the application to a login-based API. I completed tasks T1 through T10. The tasks included login, member visibility, blocking and unblocking, auto-accept cancellation, friend recommendations, cleanup of friendships after blocking, and NoUserLoggedInException.

I ended up with 69 tests: 10 tests in AccountTest and 59 tests in SocialNetworkTest. All of my tests pass.

2. What worked well?

Writing a test before changing the code helped me focus on one behavior at a time. For example, for friend recommendations, I first wrote tests for a member with two mutual friends and a member with only one mutual friend. These tests made the required behavior clear before I implemented recommendFriends().

3. What didn't work well?

The most difficult part was keeping track of which account was sending a friend request and which account was receiving it. The old methods used Account parameters, while the new methods used the logged-in account. This made some tests confusing and caused mistakes in the setup.

Another issue was the checked NoUserLoggedInException. My local tests initially passed, but the Vocareum reference tests could not compile because the exception was not declared in the interface. I had to update the interface and the implementation to use the required exception.

4. How would you do it differently next time when applying TDD?

Next time, I would create small helper methods for common actions such as sending and accepting a friend request. I would also migrate the old API tests earlier instead of keeping both APIs for so long. This would make it easier to see which account is logged in and reduce confusion in the test setup.

5. Comments and Suggestions on the Lab (Optional)

- The assignment requires both the old API and the new login-based API during the transition, which can make the code and tests difficult to follow.
- The checked exception requirement is important for the hidden tests, so it would be helpful to emphasize earlier that the exception must be declared in ISocialNetwork.
